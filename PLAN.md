# План разработки: распознавание рукописных цифр MLP на CUDA

## 1. Цель

Приложение на Python/PyTorch, которое обучает многослойную полносвязную нейросеть (MLP)
распознаванию рукописных цифр MNIST на GPU (CUDA), с раздельными обучающей,
валидационной и тестовой выборками, контролем переобучения и двухэтапным
сравнительным экспериментом.

Итог: один скрипт `run_training.py`, который обучает модель, оценивает её на
train/val/test и формирует готовые материалы для отчёта (метрики, таблицы,
графики, confusion matrix, `report.md`).

## 2. Окружение

- GPU: NVIDIA RTX 3070 (8 ГБ, sm_86/Ampere), драйвер CUDA 13.4.
- PyTorch с CUDA-сборкой из индекса `download.pytorch.org/whl/cu128` (или `cu130`).
- Python: venv на 3.12/3.13 через `uv` (системный 3.14 может не иметь колёс PyTorch).
- Зависимости: torch, torchvision, numpy, matplotlib, scikit-learn, pyyaml, tqdm.
- Критерий готовности окружения: `torch.cuda.is_available() == True`,
  `torch.version.cuda` не пустой, тестовое matmul на GPU выполняется.

## 3. Данные

MNIST: 60 000 train, 10 000 test, 28×28 grayscale, 10 классов.

Фиксированное разбиение (сохраняется в файл, переиспользуется во всех прогонах):

| Выборка | Размер | Назначение |
|---|---|---|
| Train-пул | 54 000 | источник обучающих данных |
| Validation | 6 000 | early stopping, выбор модели |
| Test | 10 000 | финальная оценка, один раз |

- Разбиение train/val — стратифицированное, seed фиксирован.
- Этап 2: из train-пула **равномерно случайно, без замены, с фиксированным seed**
  отбираются 20 000 объектов (новый обучающий набор).
- Проверки при запуске: пересечение 20k с val и test пусто; дубликатов нет;
  логируется распределение классов (≈2000 ± 40 на класс) и хеш индексов.
- Предобработка: `ToTensor` + нормализация 0.1307/0.3081, flatten в 784.
  В val/test — без аугментации и без shuffle.

## 4. Модель

MLP: **784 → 512 → 256 → 10**

- скрытые слои: Linear + BatchNorm + активация;
- Dropout 0.2–0.3 между блоками;
- выход линейный (10 логитов) + `CrossEntropyLoss`;
- инициализация: Kaiming/He для ReLU, Xavier/Glorot для tanh;
- активация задаётся конфигом: `relu` (этап 1) или `tanh` (этап 2);
- ширина скрытых слоёв — параметр: базовая 512-256 для E1, минимальная
  подбирается и обосновывается в E5.

## 5. Обучение на CUDA

- Явный `device('cuda')` с фолбэком на CPU и предупреждением.
- `DataLoader`: `pin_memory=True`, `num_workers=4–8`, `non_blocking` копирование.
- AMP: bf16 autocast (Ampere), fp32-эталон для проверки стабильности.
- AdamW: lr 1e-3, weight_decay 1e-4; планировщик по плато val loss.
- Batch size 128, максимум эпох 30, early stopping patience 5 по val loss.
- Gradient clipping (для tanh), фиксация seed, `cudnn.benchmark`, TF32.
- Чекпоинты: `best.pt` (по val) и `last.pt` + гиперпараметры, seed, версии.
- Логи эпохи: train/val loss и acc, lr, время, `max_memory_allocated`.
- Мониторинг tanh: доля насыщенных нейронов (|tanh|>0.99), норма градиента.

## 6. Эксперименты

Все прогоны используют **одни и те же** val 6k и test 10k.

| # | Train | Активация | Seed'ы | Назначение |
|---|---|---|---|---|
| E1 | 54 000 | ReLU | 1 | базовый результат (этап 1) |
| E2 | 20 000 random | tanh | 3 | требуемый (этап 2) |
| E3 | 20 000 random | ReLU | 3 | контроль: эффект объёма выборки |
| E4 | 54 000 | tanh | 1 | контроль: эффект активации |
| E5 | 54 000 | ReLU | 3 | подбор минимальной ширины скрытых слоёв (≥97 % test) |

- E2 vs E1 — сравнение этапов.
- E2 vs E3 — корректный вывод про активацию.
- Для 20k-прогонов — три разных случайных подмножества, результат mean ± std.

### E5: минимальное число нейронов скрытых слоёв (этап 1)

Цель: найти и обосновать минимальную суммарную ширину скрытых слоёв, при которой
MLP на 54 000 (этап 1, ReLU) даёт **≥ 97 % на тестовой выборке**.

Формальная постановка: минимизируем `N = n1 + n2` по всем формам `(n1, n2)`,
а не по одной пропорции. Минимум считается доказанным, если найдена форма с
`N*`, устойчиво проходящая порог, и **все** формы с меньшим `N` порог не проходят.
Поэтому перебор идёт по возрастанию `N` с перебором всех форм при каждом `N`
(включая равные и «перевёрнутые» слои), а не по одной линии 2:1.

Протокол:

1. **Грубый 2D-скрининг** (1 seed, сокращённый бюджет): `N` = 16…96 шагом 8,
   при каждом `N` — формы `(n1, n2)` с шагом 4, плюс явно 1:1, 2:1, 3:1, 4:1.
   Даёт карту «точность vs форма», а не одну кривую.
2. **Локализация порога**: в полосе 96.5–97.5 % — уточнение шагом 2–4 нейрона,
   снова по всем формам. Границы диапазона подстраиваются по результату.
3. **Подтверждение финалистов**: 5 seed'ов (или 5×2 CV на 60k) с полным бюджетом;
   сравнение кандидатов **попарно на одних и тех же объектах** val (тест МакНемара
   или парный бутстрэп), поправка Холма на множественность сравнений.
   Критерий прохождения: нижняя граница доверительного интервала ≥ 97.0 %,
   запас не менее 0.1 п.п. (non-inferiority margin).
4. **Проверка бюджета**: кандидат у порога, недобравший из-за недообучения,
   перепроверяется с лимитом 60 эпох — «не прошёл» должно означать нехватку
   ёмкости, а не нехватку обучения.
5. **Дисциплина по test**: поиск идёт только по validation; test считается для
   двух конфигураций — минимальной прошедшей и ближайшей меньшей, не прошедшей.
   Для них приводится бутстрэп-интервал, а не точечная цифра.
6. **Ортогональная проверка (опционально)**: структурный прунинг обученной сети
   512-256 до порога 97 % даёт независимую оценку порядка минимального числа
   нейронов; совпадение с сеточным результатом усиливает вывод.
7. **Отчёт**: карта/кривая «accuracy vs N» с доверительными интервалами, Парето-фронт
   `(N, accuracy)`, минимальная форма и её параметры, число параметров, время эпохи,
   явное описание пространства поиска и допущений.

Почему это точнее одной сетки:

- Точность не монотонна по `N`: форма 16+16 (`N`=32) вполне может обогнать 32+16
  (`N`=48) из-за оптимизации и регуляризации. Перебор по возрастанию `N`
  снимает эту проблему: если 16+16 проходит, минимум становится ≤ 32, и тогда
  проверяются все формы с `N` < 32 (8+8, 8+16, 16+8, 12+12 и т.д.).
- Сравнение форм корректно только при **равном** `N`: 24+24 против 32+16 (оба 48).
- Один прогон даёт SE ≈ 0.17 п.п. на test и ≈ 0.22 п.п. на val, поэтому разница
  < 0.4 п.п. на одном seed — шум. Парные тесты на общих объектах и 5 seed'ов
  позволяют различать эффекты ~0.1–0.2 п.п.
- Выбор максимума из десятков шумных прогонов завышает результат (winner's curse),
  поэтому используются интервалы, поправка на множественность и требование
  нижней границы ≥ 97 %, а не «лучший из увиденных» цифр.
- Неизменно: данные, BatchNorm, Dropout 0.2, AdamW, lr, batch 128, max 30 эпох,
  early stopping patience 5 по val loss, те же val 6k и test 10k.

Оценка объёма: скрининг ≈ 60–80 коротких прогонов (10–15 мин на GPU),
подтверждение финалистов — ещё 20–30 мин. Сети крошечные, поэтому исчерпывающий
перебор по форме практически доступен.

## 7. Метрики и отчёт

1. Accuracy и macro-F1 на val и test.
2. Learning curves train/val (loss, accuracy) — все прогоны на одних осях.
3. Скорость сходимости: эпоха достижения val acc 95 % и 98 %, время эпохи.
4. Контроль переобучения: зазор train–val, эпоха минимума val loss, срабатывание early stopping.
5. Стабильность: mean ± std по seed'ам; разница < 0.2 п.п. трактуется как незначимая.
6. Confusion matrix и топ ошибок лучшей модели.
7. Итоговая таблица: train / val / test accuracy, F1, эпохи, время, зазор.
8. E5: кривая «test/val accuracy vs суммарное число нейронов», число параметров,
   время эпохи; таблица кандидатов с mean ± std по seed'ам.
9. Точка порога 97 %: минимальная прошедшая конфигурация, ближайшая меньшая
   (не прошедшая), запас до порога и разброс.

## 9. Точка входа и конфиг

- `run_training.py` — обучение, автоматическая оценка на train/val/test и
  сборка `report.md` + `report_data.json`. Отдельного CLI и режимов нет.
- Всё, что меняется между экспериментами, задаётся в `configs/*.yaml`.
- Параметры конфига: архитектура, `activation`, `train_subset` (null|20000),
  `val_ratio`, `split_seed`, `seeds`, `max_epochs`, `patience`, `lr`,
  `batch_size`, AMP.

## 10. Этапы работ

1. Проверка/создание окружения с CUDA-PyTorch — 10–20 мин.
2. Данные и модель + smoke-тест (переобучение на 100 примерах до ~100 %) — 1 ч.
3. Цикл обучения на CUDA с AMP, early stopping, чекпоинтами — 1–2 ч.
4. Прогон E1 (этап 1), фиксация результата — минуты.
5. Прогон E5: сетка ширин, 3 seed'а, уточнение у порога, выбор минимума — 10–20 мин.
6. Случайный отбор 20k, прогоны E2/E3 (3 seed'а) и E4 — минуты–десятки минут.
7. Оценка на train/val/test, графики, `report.md` и `report_data.json` — 30 мин.
8. README с командами, таблицами и выводами — 30 мин.

## 11. Критерии приёмки

- `torch.cuda.is_available() == True`, обучение реально идёт на GPU.
- Разбиения 54k/6k/10k и 20k-подмножество проверены на отсутствие пересечений.
- Повторный запуск с тем же seed даёт совпадающие метрики (в пределах допуска).
- Этап 1: test accuracy ≥ 98.0 %; этап 2 обучен и оценён на тех же val/test.
- E5: найдена минимальная ширина с test ≥ 97 %, следующий меньший размер < 97 %,
  результат устойчив на 3 seed'ах, вывод обоснован кривой и числом параметров.
- Сформированы: `metrics.csv`, графики, confusion matrix, сводная таблица E1–E5.
- README позволяет воспроизвести все результаты командами.

## 12. Ожидаемые результаты

| Прогон | Ожидаемый test acc |
|---|---|
| E1 54k + ReLU | 98.3–98.6 % |
| E2 20k + tanh | 97.6–98.2 % |
| E3 20k + ReLU | 97.8–98.3 % |
| E4 54k + tanh | 98.1–98.5 % |
| E5 минимальная ширина (54k + ReLU) | 97.0–97.5 %, порог ≈ 48–64 нейрона |

Выводы формулируются раздельно: вклад сокращения выборки (≈0.3–0.5 п.п.)
и вклад активации (≈0–0.3 п.п.); при 20k разница может быть в пределах шума,
что фиксируется как результат.

По E5 ожидаемо: 16-8 и 32-16 не достигают 97 %, 48-24 или 64-32 — достигают;
минимальная конфигурация уточняется шагом 8 нейронов. Если 32-16 проходит порог
на 3 seed'ах, минимум пересматривается вниз, до 24 нейронов.

## 13. Риски и меры

- Нет колёс PyTorch под Python 3.14 → venv на 3.12/3.13 через uv.
- Установилась CPU-сборка → проверка `torch.version.cuda`, переустановка с `--index-url`.
- Утечка val/test в обучение → программная проверка пересечений, фиксированные индексы.
- Нестабильность AMP → fp32-эталон, bf16 как ускоренный вариант.
- Незначимые различия → 3 seed'а, mean ± std, а не один прогон.
- Насыщение tanh → BatchNorm, Xavier, gradient clipping, мониторинг насыщенности.
- Подгонка под test при поиске ширины → поиск по val, test только для финальной пары.
- Ложный вывод «мало нейронов» из-за недообучения → перепроверка у порога с лимитом 60 эпох.
- Разброс на малых сетях → 3 seed'а, критерий mean − std, фиксация std в таблице.
